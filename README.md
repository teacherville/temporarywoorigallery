# 우리반 전시회

아이들 그림을 3D 미술관에 걸고, 반 친구들이 코드 하나로 함께 들어와 둘러보는 웹페이지예요.
선생님도 아이들도 로그인이 필요 없어요. 선생님은 그냥 전시회를 만들고, 아이들은 코드나 QR로 들어와요.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 화면, 디자인, 3D 전시관, 실시간 함께 보기가 모두 들어 있는 한 파일 (맨 위 `FIREBASE_CONFIG`에 파이어베이스 설정) |
| `favicon.png` | 브라우저 탭 아이콘 |
| `apple-touch-icon.png` | 휴대폰 홈 화면에 추가할 때 아이콘 |
| `thumbnail.jpg` | 카카오톡·문자로 링크를 보낼 때 뜨는 미리보기 사진 (1200×630) |
| `database.rules.json` | 파이어베이스 보안 규칙 (콘솔에 붙여 넣는 용도, 사이트에는 안 올려도 돼요) |
| `guide.html` | 선생님용 "우리 반 전용 서버 연결" 안내 페이지 (`…/woorigallery/guide.html`). 설정값을 붙여 넣으면 연결 상태를 점검하고 저장해요 |

## 처음 한 번만 하는 준비

### 1. 파이어베이스 프로젝트 만들기
1. [console.firebase.google.com](https://console.firebase.google.com)에서 새 프로젝트를 만들어요.
2. **빌드 → Realtime Database → 데이터베이스 만들기**를 눌러요. 위치는 가까운 곳(싱가포르 등)을 고르고, 잠금 모드로 시작해요.
3. **규칙** 탭에 `database.rules.json` 내용을 통째로 붙여 넣고 **게시**해요.
4. **빌드 → Authentication → 시작하기 → 로그인 방법 → 익명**을 사용 설정해요. (선생님 기기를 알아보는 데만 쓰여요. 아이디·비밀번호를 만드는 게 아니에요)
5. **프로젝트 설정(톱니바퀴) → 내 앱 → 웹 앱 추가(</>)**를 누르면 `firebaseConfig`가 나와요.
   이 값을 `index.html` 맨 위 `window.FIREBASE_CONFIG`에 옮겨 적어요. `databaseURL`도 꼭 넣어 주세요.

### 2. 깃허브 페이지로 올리기
1. 깃허브에서 새 저장소를 만들고 `index.html`, `favicon.png`, `apple-touch-icon.png`, `thumbnail.jpg` 네 파일을 같은 곳에 올려요. (예전에 올린 `style.css`, `app.js`는 지워도 돼요)
2. 저장소의 **Settings → Pages**에서 Branch를 `main`, 폴더를 `/ (root)`로 정하고 저장해요.
3. 1~2분 뒤 `https://teacherville.github.io/woorigallery/` 주소가 생겨요.
4. 링크 미리보기(썸네일) 주소는 `https://teacherville.github.io/woorigallery/`로 이미 넣어 두었어요. 저장소 이름을 바꾸면 `index.html` 위쪽 `og:url`, `og:image` 두 줄도 같이 바꿔 주세요.
   (카카오톡은 미리보기를 한동안 기억해요. 바꾼 뒤에도 예전 모습이 뜨면 [카카오 공유 디버거](https://developers.kakao.com/tool/debugger/sharing)에서 주소를 넣고 초기화하면 돼요)

## 썸네일 새로 만들기 (필요할 때만)
1. 배포한 주소 끝에 `?thumb`를 붙여 PC에서 열어요. (예: `https://teacherville.github.io/woorigallery/?thumb`)
2. 7초쯤 기다리면 전시관 앞모습과 ‘우리반 전시회’ 제목이 담긴 `thumbnail.jpg`(1200×630)가 저절로 내려받아져요.
3. 그 파일을 저장소에 올려요.

## 수업에서 쓰기
1. 깃허브 주소로 들어가서 **선생님 → 전시회 만들기**를 눌러요.
2. 반, 주제, 작품 사진을 넣고 저장하면 6자리 입장 코드와 QR, 그리고 **관리 코드**가 나와요.
3. 아이들은 같은 주소에서 **코드로 입장하기**를 누르거나 QR을 찍어서 들어와요.
4. 같은 코드로 들어온 친구들은 서로의 캐릭터를 보고, 박수·칭찬·쪽지가 바로 함께 보여요.
5. 수업이 끝나면 내 전시회 목록의 **⋯ → 전시 닫기**로 닫아 둘 수 있어요. 입장만 막히고 데이터는 남아요.
6. 다 쓴 전시회는 **⋯ → 지우기**를 눌러야 작품과 아이들이 남긴 글이 실제로 지워져요.

## 관리 코드
- 전시회는 처음 만든 기기(브라우저)에서 바로 고칠 수 있어요.
- 다른 컴퓨터나 태블릿에서 고치려면 그 기기에서 **선생님 → 관리 코드로 불러오기**를 누르고 관리 코드(예: `ABC123-K7Q2MX`)를 넣어요.
- 관리 코드는 전시회 목록의 **⋯ → 관리 코드 보기**에서 언제든 다시 볼 수 있어요. 아이들에게는 알려 주지 마세요.
- 브라우저 기록을 지우면 그 기기의 목록이 비어요. 관리 코드로 다시 불러오면 돼요.

## 비용
- 이 구성은 파이어베이스 **무료 요금제(Spark)**만으로 돌아가요. 카드를 등록하지 않으면 요금이 나갈 일이 없어요.
- 무료 한도와 넘었을 때 생기는 일은 항목마다 달라요.

| 한도 | 넘으면 |
| --- | --- |
| 동시 접속 100명 (25명 반 기준 약 4개 반) | 이미 들어온 사람은 계속 쓰고, **새로 들어오려는 사람만** 막혀요. 자리가 비면 다시 들어와요 |
| 한 달 다운로드 10GB | **앱 전체가 꺼지고 그달 내내** 아무도 못 써요 |
| 저장 1GB (전시회 약 300개) | 새 전시회를 저장할 수 없어요 |

- 여기서 다운로드는 파일을 내려받는 게 아니라, 아이들 기기에 작품 사진과 실시간 정보를 보내 준 양이에요. 25명 반이 한 번 들어오면 약 75MB예요.

## 운영 관리 (공용 주소)

### 접속이 몰릴 때
- 연결이 9초 넘게 안 되면 화면 위에 "접속이 몰려 연결이 늦어지고 있어요" 안내와 **새로고침**, **우리 반 전용으로 만들기** 버튼이 떠요. 연결되면 저절로 사라져요.
- 전용으로 만들기 버튼은 `guide.html`로 연결돼요. 선생님이 자기 파이어베이스를 만들어 연결하는 방법이 적혀 있어요. 아래 **우리 반 전용 서버**를 봐 주세요.
- 첫 화면의 **꼭 읽어 주세요 · 이용 안내**에도 같은 내용과 연결 버튼이 있어요.

### 사용량 확인 (매일 권장)
- 파이어베이스 콘솔 → **Realtime Database → 사용량** 탭에서 연결, 저장, 다운로드를 그래프로 볼 수 있어요.
- **다운로드를 가장 먼저 보세요.** 한 달에 10GB를 넘으면 그달 전체가 멈춰요. 월 중순에 5GB를 넘었다면 위험 신호예요.
- 연결 그래프가 100에서 평평하게 막혀 있으면 그 시간대에 못 들어온 사람이 있었다는 뜻이에요.

### 관리자 권한
- 파이어베이스 프로젝트를 만든 구글 계정이 최고 관리자예요. 콘솔에서는 모든 전시회를 보고 지울 수 있어요.
- 담당자가 바뀌어도 관리할 수 있게 **톱니바퀴 → 사용자 및 권한**에서 팀원 계정을 **소유자**로 추가해 두세요.
- 콘솔에서 전시회 하나를 직접 지우려면 같은 6자리 코드를 `codes`, `keys`, `claims`, `works`, `claps`, `clapn`, `notes`, `wall`, `live`, `audio`에서 모두 지워야 해요. 가능하면 선생님이 앱에서 **⋯ → 지우기**를 쓰게 안내해 주세요.
- 날짜 값(예: `updatedAt: 1794295417258`)은 1/1000초 단위 숫자예요. 엑셀에서 `=A1/86400000+DATE(1970,1,1)+9/24`로 한국 시간으로 바꿔 볼 수 있어요.
- 지금은 **학생이 마지막으로 들어온 날짜는 기록되지 않아요.** `updatedAt`은 선생님이 마지막으로 저장한 시각이에요.

### 데이터 위치와 개인정보
- 데이터베이스 위치는 **싱가포르**(`asia-southeast1`)예요. Realtime Database는 미국, 벨기에, 싱가포르 중에서만 고를 수 있어요.
- 이름, 연락처 같은 개인정보는 받지 않는 구조로 운영해요. 작품에는 번호나 별명을, 사진은 실명이나 얼굴이 보이지 않게 올리도록 안내해 주세요.

## 우리 반 전용 서버 (깃허브 없이)
공용 서버가 붐빌 때, 선생님이 자기 구글 계정의 무료 파이어베이스를 만들어 **같은 주소에서** 쓰는 방식이에요.

**작동 방식**
- 선생님이 `guide.html` 5단계에 설정값을 붙여 넣으면, 연결을 점검한 뒤 그 브라우저에 저장해요(`localStorage`의 `wg_own_db`). 그 기기에서는 이후 선생님 서버를 써요.
- 선생님이 공유하는 링크·QR에는 서버 정보가 `?db=…`로 붙어요. 아이들 기기는 이 링크로 들어올 때만 선생님 서버를 쓰고, 따로 저장하지 않아요.
- 6자리 코드만 넣어도 들어와요. 선생님이 전용 서버에 전시회를 저장할 때 공용 DB의 `ptr/{코드}`에 "이 코드는 이 서버" 표시(apiKey, databaseURL, projectId)를 한 번 남기고, 아이가 코드를 넣으면 공용 DB에서 그 표시를 한 번 읽어(REST, 실시간 연결 아님) 선생님 서버로 옮겨 가요.
- `ptr`는 처음 한 번만 쓸 수 있고 덮어쓰거나 지울 수 없어요(공용 `database.rules.json`의 `ptr` 규칙). 전시회를 지워도 표시는 남지만, 그 코드로는 "찾지 못했어요"가 떠요.
- 첫 화면의 **공용 서버로 돌아가기**나 `guide.html` 위쪽 버튼으로 연결을 끊을 수 있어요.
- 저장되는 건 `apiKey`, `databaseURL`, `projectId` 세 값이에요. 모두 원래 공개되는 값이에요.

**알아 둘 점**
- 화면 코드는 공용 주소 것을 같이 써요. `index.html`을 고치면 전용 서버를 쓰는 선생님에게도 바로 반영돼요. **DB 구조나 `database.rules.json`을 바꾸면 이미 연결한 선생님들의 규칙과 맞지 않게 돼요.** 규칙을 바꿀 때는 예전 규칙에서도 돌아가게 해 주세요.
- 링크의 `?db=` 값은 누구나 만들 수 있어요. 티처빌 주소와 화면으로 티처빌이 관리하지 않는 서버의 내용이 보일 수 있다는 뜻이에요. 그래서 전용 서버로 열린 화면의 이용 안내에는 "티처빌은 저장된 내용을 보거나 관리하지 않아요"가 나와요.

## 알아 두면 좋은 것
- 작품 사진은 데이터베이스에 작게 줄여서 저장해요(한 장에 약 100KB 이하). 한 전시회에 30점이면 3MB 정도예요.
- 아이 이름은 코드를 아는 사람에게 보여요. 번호나 별명으로 적는 걸 권해요.
- 문제가 생겼을 때 주소 끝에 `?debug`를 붙여 들어가면 화면 아래에 오류 내용이 보여요.
